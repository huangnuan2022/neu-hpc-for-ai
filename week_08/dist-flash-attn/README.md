# Distributed FlashAttention-Style CUDA/NCCL Microbenchmark

This directory contains the custom-kernel path of the Distributed LLM Serving & GPU Optimization System. It is an independent FP32, single-head attention microbenchmark; it is not integrated into vLLM and is not the kernel used by the Qwen3-8B serving path.

## Implemented Algorithm

- Numerically stable online softmax with running `(m, l, accumulator)` state.
- Sequence sharding across 1, 2, or 4 GPUs.
- NCCL ring rotation of K/V shards.
- Persistent workspaces that create communicators, streams, events, and buffers before warm-up.
- Double-buffered K/V rotation using separate compute and communication streams.
- CUDA-event timing per device, reported as the maximum participant duration.
- Warm-up and repeated samples with median and p95 reporting.
- Full-output correctness fixtures generated by PyTorch SDPA.
- Exact requested workspace bytes and observed `cudaMemGetInfo` allocation deltas.

## Build

Requirements are CUDA, NCCL, CMake 3.18+, and a C++17 compiler:

```bash
cmake -S . -B build
cmake --build build -j
```

## Correctness

Generate a small trusted fixture on a machine with PyTorch:

```bash
python3 scripts/generate_sdpa_fixture.py \
  --output-dir results/sdpa-seq128 \
  --seq 128 \
  --dim 64

./build/dist_flash_attn \
  --case-dir results/sdpa-seq128 \
  --gpus 4 \
  --warmup 5 \
  --iterations 20
```

The binary reports maximum absolute and relative error for the complete output tensor. PyTorch SDPA is named as the reference only when `--case-dir` is supplied; otherwise the distributed result is compared with the custom single-GPU implementation.

## Reproducible Sweep

Run sequence lengths 1,024, 2,048, and 4,096 at every available configuration in the 1/2/4-GPU matrix:

```bash
python3 scripts/run_gpu_sweep.py \
  --max-gpus 4 \
  --correctness-case results/sdpa-seq128 \
  --output-dir results/a10g-4gpu
```

For each multi-GPU shape, the sweep runs both overlap-enabled and serialized K/V rotation. It writes JSON with all samples and a Markdown method/results report. Setup and K/V input staging are excluded from the steady-state duration; state initialization, kernels, NCCL rotation, and finalization are included.

## Memory Accounting

For sequence length `S`, dimension `D`, and `G` GPUs using FP32:

- Full materialized score matrix: `S * S * 4` bytes.
- Minimal per-GPU ring state: `2 * (S/G) * 4 + (S/G) * D * 4 + 2 * (S/G) * D * 4` bytes for `(m,l)`, accumulator, and the current K/V shard.
- Explicit double-buffer workspace: minimal state plus a second K/V shard pair.

At `S=4096`, `D=64`, and `G=4`:

- Full score matrix: `67,108,864` bytes.
- Minimal ring state: `794,624` bytes/GPU, a formula-based `98.8159%` reduction.
- Explicit double-buffer workspace: `1,318,912` bytes/GPU, a `98.0347%` reduction.

The 98.8% figure applies only to minimal algorithmic working state. Benchmark JSON also records exact explicit workspace bytes and observed CUDA free-memory deltas so the implementation overhead stays visible.
